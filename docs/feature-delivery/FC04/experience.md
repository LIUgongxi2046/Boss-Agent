# FC04 经营提醒体验

入口为scripts/run_fc04.command，沿用validation/.work/mvp01-experience的既有资料和账号，从F02打开。当前体验窗口、进程和资料由本人决定何时切换；切换时关闭原桌面后启动此入口。账号文件为该目录accounts/credentials.json，账号内容不写入文档。启动不自动修改配置、启用规则、创建事件或恢复已取消计划。

1. 通过技术维护登录，在A13查看当前技术配置，分别保存草稿、校验版本和启用。经营关注规则使用同页的独立区域，维护仅能保存、校验并启用完整获准演示参数；本人可以在F02独立调整关注规则。本人通知设置位于N08，需要单独保存及本人确认。
2. A13选择获准经营观察并明确载入。MARGIN_DROP以获准BASE/CURRENT明细计算，连续观察间隔五分钟、持续十分钟；通过A04明确推进当前业务时钟后，再次载入观察。其他观察类型来自显示的获准定义。时钟只向前推进，不通过启动重置资料。
3. 本人在F02或N06读取事实、比较期间、截至时间、持续时间、参与条件、来源、缺少条件、当前规则及调度/抑制/恢复记录。来源失效时停止采用事实和原文。助手实际SDK只读取notifications投影；需要配置时，维护在A08正常保存、校验并明确启用，不自动调整工具权限。
4. 分别确认知晓、暂缓、会议关联、交办或关闭。暂缓提供业务时钟之后三十分钟选择，到期重新核查当前条件。关联会议不安排或发送；创建交办为OPEN，打开关联F06后填写正文并独立确认模拟发送。关闭提醒不修改源事件、任务状态或期限。
5. 请求系统通知前明确勾选确认。通知只包含通用类别和返回入口，显示结果与内部保存分别表达。当前设备报告系统拒绝，应用内仍可处理，系统成功显示/点击尚未确认。
6. 写入结果未知时只查询原动作与编号。刷新后原确认框只能核查，重新认证后只能主动只读查询原回执；不会重放或恢复原授权。计划暂停、取消及授权撤销后的抑制原因可读。

全部外部SIMULATED_FIRST，没有新真实外部请求；资料、可信标记和阈值属于明确演示定义。当前本机依赖方式可启动，独立安装、视觉、真实外部投递、系统成功显示/点击及用户共同验收未确认。FC04开发覆盖20项与用户待验收分别登记；后续业务暂停，只接续已授权UI01，完成后等待用户。
