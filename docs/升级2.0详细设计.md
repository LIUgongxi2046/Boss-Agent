# Boss-Agent 升级2.0详细设计

doc_id：DOC-LLD-2；版本：2.0.0；日期：2026-10-30；任务：UPGRADE-2-DESIGN；状态：IN_REVIEW。依据为 [PRD2.0](PRD2.0.md) 和 [HLD2.0](HLD2.0.md)。本文件定义跨数据、后端、Agent和前端的新增接口，全部为待实施设计；当前物理结构继续参照 [数据字典](当前数据字典.md)。

## 1. 共同字段与状态规则

所有ID由产品服务生成，使用UUID；时间存储为含时区的ISO 8601 UTC，业务显示采用计划时区。`business_time`单独表达模拟业务时刻。`revision`、`seq`、`lease_epoch`为单调递增整数。金额与指标采用已有Decimal精度、单位、币种和期间规则。自由正文与文件内容不放入技术审计事件。

| 对象 | 必要字段 | 生产者与消费者 |
|---|---|---|
| Run | `run_id, goal_id, goal_revision, conversation_id, parent_run_id, engine, engine_revision, model_config_revision, actor_id, space_id, scope_revision, status, lease_epoch, budget, created_at, updated_at` | RunBroker生产；页面、Bridge、审计消费 |
| SourceRef | `source_id, revision, locator, classification, business_time, retrieved_at` | 领域服务生产；成果、上下文与验证消费 |
| Event | `event_id, run_id, seq, type, occurred_at, trace_id, payload_version, payload` | RunBroker保存；页面重放、审计消费 |
| Intent | `intent_id, run_id, action, object_id, expected_revision, payload_digest, scope_revision, authorization_id, status, result_ref` | 领域服务生产；确认UI与执行工具消费 |
| Artifact | `artifact_id, run_id, version, media_type, storage_key, sha256, size_bytes, source_refs, verification_status, status` | ArtifactService生产；页面与导出消费 |
| Error | `code, message, run_id, trace_id, failed_step, completed_refs, recovery_action` | 失败入口生产；页面显示允许的后续操作 |

`actor_id`、`space_id`、授权和租约只能由服务端注入，用户表单或模型提供的同名字段一律拒绝。`budget`必须包含有限正值的轮次、工具数、时限、并发、上下文与文件额度；配置缺少或不合法返回`BUDGET_NOT_CONFIGURED`。具体值由U2-01验收后固定。

### 1.1 状态转换

| 当前状态 | 允许目标 | 必要条件 |
|---|---|---|
| QUEUED | RUNNING、CANCELED、FAILED | 有效租约启动；未启动取消；启动检查失败 |
| RUNNING | WAITING_INPUT、WAITING_CONFIRMATION、CANCEL_REQUESTED、RECONCILING、SUCCEEDED、FAILED、INTERRUPTED | 每个转换附实际事件，成功须覆盖全部必要成果 |
| WAITING_INPUT | RUNNING、CANCEL_REQUESTED、FAILED、INTERRUPTED | 输入与当前来源核查通过；取消；失效；退出 |
| WAITING_CONFIRMATION | RUNNING、CANCEL_REQUESTED、FAILED、INTERRUPTED | 匹配确认；拒绝后按已明确剩余目标继续；失效或退出 |
| CANCEL_REQUESTED | RECONCILING、CANCELED、INTERRUPTED | 有未知动作；全部在途已核查；进程退出 |
| RECONCILING | RUNNING、WAITING_INPUT、CANCELED、FAILED、INTERRUPTED | 仅查询原意图，确认结果后按取消标识和目标继续 |
| INTERRUPTED | RECONCILING、QUEUED、CANCELED | 存在未知动作先核查；合法继续并刷新租约；无在途后取消 |
| SUCCEEDED、FAILED、CANCELED | 无 | 终态不可改写；新要求或重新执行创建新运行并保存关联 |

`cancel_requested_at`独立保存且不可由引擎清除；存在该字段的运行不能继续新动作。`SUCCEEDED`仅表示本次目标达到验收条件，不能代替业务任务的本人验收。

## 2. 数据设计

### 2.1 新增逻辑表

由现有产品存储维护，不为Hermes开放数据库连接。现有领域对象类型及账号表保持。实施时由版本化迁移文件建立表、外键和索引，Schema与本文同时更新。

| 表 | 主要内容 | 约束与索引 |
|---|---|---|
| `agent_runs` | Run字段、目标正文引用、租约、取消标识、结果摘要引用 | PK `run_id`；索引`space_id, conversation_id, created_at`；状态CAS使用`revision` |
| `agent_run_events` | Event字段；payload为版本化JSON | UNIQUE `run_id, seq`和`event_id`；外键run；序号在事务内分配 |
| `agent_run_inputs` | 输入ID、运行、目标版本、正文引用、采用事件 | UNIQUE `run_id, input_seq`；每条补充仅采用一次 |
| `agent_request_keys` | 主体、空间、请求键、请求摘要、运行引用 | UNIQUE `actor_id, space_id, request_key`；不同摘要冲突 |
| `agent_intents` | Intent字段、确认预览、消费时间与回执 | UNIQUE `intent_id`；领域幂等键稳定绑定该ID |
| `agent_artifacts` | Artifact字段、创建与撤销时间、内容核查结果 | UNIQUE `artifact_id, version`；storage_key只能指向获准文件根目录 |
| `agent_context_refs` | run、来源/记忆/方法/配置ID、版本与采用状态 | 索引`ref_kind, ref_id, revision`，支持撤销传播 |
| `agent_schedule_occurrences` | 计划、版本、发生时间、运行与调度租约 | UNIQUE `schedule_id, revision, occurrence_at` |

计划抑制历史查询采用当前本人计划、计划版本和事件编号确定查询范围，读取该事件当前版本的全部 `SUPPRESSED` 派发记录，逐条核查原回执摘要。每条返回实际 `dispatch_id`；存在唯一可核查发生关联时返回 `occurrence_id` 和 `run_id`，没有关联时返回空值及 `UNVERIFIED`，关联不唯一时拒绝。服务要求本人角色并在读取前后核查身份；正式路由和调度仍受既有门禁约束。返回字段由 `validation/agent_schedule_history_schema.json` 定义。
| `agent_migrations` | 迁移版本、输入摘要、状态、备份引用与核查结果 | 相同版本和输入摘要幂等；不记录秘密 |

现有授权、审计和业务回执继续保留原存储。新增`authorization_id`必须引用现有合法授权，不能在运行表中自行产生授权事实。领域动作与其回执在同一事务提交；运行事件通过持久结果补充生成，即使事件发布中断也能从原回执恢复。

### 2.2 意图和成果

意图状态为PREPARED、WAITING_CONFIRMATION、AUTHORIZED、EXECUTING、SUCCEEDED、FAILED、UNKNOWN、REJECTED、EXPIRED。授权覆盖`actor_id + action + object_id + expected_revision + payload_digest + scope_revision + expiry`；采用规范化JSON摘要算法及成熟实现，禁止自行编写格式解析器。任何关键字段变化生成新预览，原授权不能继续使用。

成果状态为DRAFT、VERIFIED、PUBLISHED、REVOKED、FAILED。生成文件先位于当前运行工作区，由对应成熟解析库读取并核对任务要求，再计算摘要并登记。登记失败时文件保持未发布；导出核查版本、摘要及当前权限，禁止通过路径参数读取任意文件。源资料撤销后阻止旧成果继续作为有效依据，历史记录显示撤销原因。

来源撤销后，原成果请求的待登记正文已清理且文件结果未知时，可按原运行查询待核查请求列表及单项状态，只读返回原运行编号、请求编号、成果编号、RECONCILING 和 null 成果。接口核查本人角色、原运行主体、当前执行空间、原生会话实例及该会话的有效订阅，并核查原来源范围与撤销状态；不得返回来源正文、文件内容或文件路径。页面独立于运行快照读取列表，身份、会话、运行或连接变化时清除旧响应。文件是否写入尚未证明时保留 RESERVED 预算和文件，不能凭该状态宣称清理完成。正式成果读取隔离门禁保持适用。

### 2.3 迁移核查

每类旧数据建立输入版本、条数、主键集合、摘要和关联关系基准。迁移验证包括空库、已有个人操作、重复迁移、版本冲突、文件缺失、备份恢复及撤销传播。迁移不能修改旧用户确认结果，也不能为已有模拟记录增加真实外部执行标记。迁移成果与原数据分别保存直到恢复验证完成。

## 3. 后端与接口

### 3.1 产品API目标

下表均为待实现接口；认证采用产品当前账号体系，修改动作保留会话、来源与CSRF防护要求。请求Schema在U2-02中新增，现有OpenAPI文档继续说明现有接口。

| 方法与路径 | 输入 | 返回及权限 |
|---|---|---|
| `POST /api/v2/runs` | `conversation_id, goal, selected_refs, request_key` | `run_id, status, revision`；服务端核查当前BOSS |
| `GET /api/v2/runs/{run_id}` | 当前登录身份 | Run投影、成果、待处理输入与确认；私密字段按身份过滤 |
| `POST /api/v2/runs/{run_id}/inputs` | `input, expected_goal_revision, request_key` | 输入编号与新目标版本；过期版本409 |
| `POST /api/v2/runs/{run_id}/cancel` | `expected_revision, request_key` | 当前取消状态和已完成引用；同请求幂等 |
| `POST /api/v2/runs/{run_id}/resume` | `expected_revision, request_key` | 原运行合法继续结果；终态返回明确冲突 |
| `POST /api/v2/intents/{intent_id}/decision` | `decision, expected_revision, payload_digest, request_key` | 本人确认或拒绝回执；模型无此入口权限 |
| `GET /api/v2/runs/{run_id}/events` | `after_seq` | 有序持久事件及下一游标；支持WS订阅同一事件模型 |
| `GET /api/v2/artifacts/{artifact_id}` | 版本与登录身份 | 元信息、当前资格和受限内容访问入口 |
| `POST /api/v2/artifacts/{artifact_id}/export` | 目标授权引用、版本、请求键 | 文件导出结果；目标由宿主验证 |

修改请求只接受明确Schema字段，多余主体或授权字段拒绝。HTTP语义：400输入不合法；401认证无效；403权限不足；404不存在或无权获知的对象；409版本/请求键冲突；413输入超限；422来源或格式不符合要求；429容量超限；503依赖不可用。错误正文采用统一Error结构，`recovery_action`为允许动作枚举，不能指示自动重复未知写入。

### 3.2 Bridge目标协议

握手包含`protocol_version, engine_commit, environment_digest, capabilities`；产品核对固定版本与必需能力后才接受运行。每个启动请求携带服务端生成的`run_id, lease_epoch, context_refs, tool_policy_ref, budget, checkpoint_ref`。内部凭据绑定实例、运行和期限，不含产品登录Cookie。

Bridge生产RUN_STARTED、INPUT_APPLIED、TOOL_STARTED、TOOL_FINISHED、ARTIFACT_CANDIDATE、INPUT_REQUIRED、INTENT_PREPARED、USAGE_RECORDED、RUN_FINISHED和RUN_FAILED等实际事件；RunBroker验证序列、类型和租约，转换为产品事件。RUN_FINISHED只是引擎完成信号，产品验证必要成果后决定SUCCEEDED。未知事件版本返回协议错误。

业务工具返回结构化`result, source_refs, business_receipt, error`；结果未知明确UNKNOWN并附原意图编号。连接超时与业务失败分开记录。恢复只查询原意图；若无法确定结果，保持RECONCILING，不通过新请求尝试同一写入。

### 3.3 并发与持久事件

每个运行只存在一个有效租约epoch；每个会话的目标补充串行采用。多个独立运行的业务冲突由领域CAS判定。事件在SQLite事务内分配序号并保存后推送；客户端缺少序号时请求重放。连接断开不代表运行取消，关闭桌面按明确生命周期规则触发中断与在途核查。

## 4. Agent、工具与方法

### 4.1 接入责任

受管隔离采用用户批准的独立 Linux 虚拟机配置，宿主持有虚拟机身份、生命周期及运行工作区边界。客体按配置 UUID 核查独立工作区磁盘，每个运行的专属目录映射至该运行私有命名空间内的 `/mnt`。客体默认无网络设备；安装阶段若需网络，须限定至获准系统及依赖来源，安装结束移除设备。目标客体的服务自启动、磁盘挂载与宿主认证已有技术证据；宿主与客体工作区关联、文件额度和累计 CPU 上限仍需联合验证，未通过时运行创建继续受门禁约束。环境安装记录及当前限制见 U2-03。

独立虚拟机入口、权限、客体服务及串行安装配置保存在 [scripts/managed_linux](../scripts/managed_linux/README.md)。宿主控制身份接口已通过 Virtio Socket 和双向 TLS 实际检查；客体运行账号与监督服务已有独立技术检查。产品派发、工作区映射、累计额度及异常恢复仍需完成并联合验证，正式运行保持关闭。

Hermes负责模型循环、按需方法加载和受限子任务。HermesBridge负责与固定版本API适配，不能在模型之外生成固定成功答案。官方`AIAgent.run_conversation`的实际参数、回调及checkpoint能力在U2-01中验证；本文件不把自定义Bridge方法声明为上游现成API。

| 工具类别 | 当前复用入口 | 升级约束 |
|---|---|---|
| 经营与对象读取 | `conversation_agent`、`product_*`、`boss_*`的领域读取 | 按来源资格与范围校验，返回结构化值和引用 |
| 计算与核查 | 现有指标计算、Decimal及来源验证 | 禁止模型自行填补缺少数据 |
| 准备业务动作 | 现有命令及`sop_write_tools`的适用服务 | 生成Intent及预览，无自动本人确认 |
| 执行业务动作 | 领域授权、CAS、幂等与回执 | 只消费完全匹配授权，执行后重读 |
| 文件读取与生成 | 新增受限文件服务及成熟第三方库 | 仅当前工作区与获准输入；五格式真实核查 |
| 方法候选 | 现有`agent/skills/`与新增候选记录 | 只写候选区；发布需要技术核查与相应授权 |
| 个人记忆 | 现有本人记忆服务 | 只读有效版本；新增与修改走本人确认 |
| 计划与提醒 | 现有计划语义、目标Hermes cron驱动 | 唯一触发方；先核查计划、范围和当前授权 |

### 4.2 失败与预算

工具调用前检查类别、资料、权限、租约和剩余额度，任意条件不满足立即返回错误。文件解析直接使用所需依赖，导入失败阻止启动相应能力；禁止用替代输出通过检查。模型API错误保留原错误类别和请求关联，秘密脱敏；不自动更换Provider或生成模拟回答。

内部子任务具有父运行和独立运行编号，权限只能收窄，写入正式业务的请求由主运行汇总为意图。取消父运行使子任务禁止新动作；所有辅助模型调用、方法生成和核查调用均计入父预算。结果冲突保留双方证据并明确待核查，不能通过多数回答认定业务事实。

## 5. 前端与交互

保持Desktop v7现有布局、导航和页面ID。运行交互在现有聊天、任务详情、文件详情和管理页面内接入，新增状态不增加员工账号或部门工作台。

| 页面区域 | 数据来源 | 操作及异常表现 |
|---|---|---|
| N02聊天执行区 | Run快照与持久事件 | 目标、实际步骤、补充、取消；断线显示重连状态并按序号重放 |
| N02确认卡片 | Intent当前预览 | 完整对象、内容、期限、影响、来源版本及模拟标识；过期后读取当前预览 |
| N04/F24成果区域 | ArtifactService | 格式、大小、核查状态、引用、打开与导出；失效文件明确说明 |
| N05任务及F24/F29详情 | 业务任务与关联运行分别读取 | 区分执行成功和本人业务验收；点击进入同一正式对象 |
| N07本人目标与关注要求/F13个人记忆 | 当前有效目标、关注要求与记忆 | 查看、修改、删除和传播状态；维护身份不显示私人正文 |
| N06/N08/N09与A13 | 业务计划及派生触发投影 | 暂停、恢复、取消和最近运行；显示时区与模拟业务时间 |
| A05—A10、A15/A16 | Prompt、方法、知识、模型、工具、指标规则及运行元信息 | 候选与有效版本分别显示；缺少兼容证据不能显示可运行 |
| 全部72页 | 原领域接口与当前权限 | 加载、空数据、失败、拒绝、取消、来源变化和键盘行为全部保留 |

同一事件不重复插入消息；运行进展和正文结果分别渲染。按钮可用性由服务端允许动作确定，前端禁用仅作为提示。敏感确认使用键盘可达的独立操作区，焦点返回原触发位置；不得因流式更新抢夺输入焦点。数字来源与原文入口使用实际SourceRef，无法定位时显示准确失败。
