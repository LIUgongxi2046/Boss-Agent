# 开发接手与执行规范

doc_id：DOC-HANDOVER；维护责任：当前接手负责人；文档规则状态：CURRENT；核查日期：2026-10-25。

本规范适用于每次任务开始、聊天恢复、开发交接和交付。每次必须完整阅读；产品范围和完成数量从下列唯一来源读取。具体实施范围采用当前用户授权，规范建立不表示业务修复已经完成。

## 1. 产品与执行范围

产品服务一位老板，提供个人秘书、经营关注、会议资料、交办与承诺等能力；MAINTAINER负责技术配置和获准模拟资料，联系人属于资料对象。完整需求和全部设计继续保留，不根据已有代码缩减。

当前执行方式为全部Desktop v7前端优先，随后完成后端和Agent接入，按用户要求集中执行必要验证。活动任务、工单、候选、交付入口和验收状态仅从 [feature-delivery.json](../specs/feature-delivery.json) 读取；页面目录从 [menu-plan.json](../specs/menu-plan.json) 读取。文档内的阶段编号和累计描述不触发任务切换。

当前用户约束包括：外部能力采用显式SIMULATED_FIRST；语音任务暂停；禁止主动视觉、截图和图像查看；保护用户正在使用的进程与资料。2026-10-25用户明确停止定时监督，本规范不恢复自动化、不启动开发聊天。自动认证及初始化认证的待确认事项继续按正式记录处理，表单填充授权不扩展为自动登录授权。

## 3. 工程与运行入口

正式仓库为`origin`对应的Boss-Agent，发布分支为`main`。工作目录通过`pwd`、`git status --short`、`git branch --show-current`及`git rev-parse HEAD`确认。不得将任意工作目录中的未提交文件视为main成果。

| 位置 | 当前职责 |
|---|---|
| `app/webui/` | 产品React组件、CSS及nanobot接收补丁 |
| `validation/application.py`、`validation/product_*.py`、`validation/boss_*.py` | 实际产品入口、公共适配和领域服务；目录名称不表示内容仅用于测试 |
| `validation/conversation_agent/`、`validation/sop_write_tools/` | 会话与业务工具适配 |
| `agent/skills/` | 产品SOP方法正文 |
| `specs/` | 接口、Schema、需求映射及当前执行状态 |
| `scripts/prepare_boss_webui.py` | 固定上游源码与前端准备入口；完整复制及补丁应用列入第7节接手必核项 |
| `validation/desktop/` | Electron宿主及桌面检查 |
| `app/tests/`、`evidence/` | 检查程序及限定版本证据 |
| `.work/`、`validation/.work/`、各功能`*-dist/` | 本机生成目录；不能成为重建产品所需的唯一源码来源 |

已有N1/N2/N3/N4工作目录与角色从当前工单读取。跨目录读取可以用于核查，修改遵守任务归属。原始目录、集成目录、制品和运行实例分别核对；不得直接覆盖其他人的修改。

依赖入口为`validation/pyproject.toml`及锁文件、`validation/desktop/package.json`及锁文件。现有准备命令为`python3 scripts/prepare_boss_webui.py --build`，通用启动入口为`bash scripts/run_boss_local.sh`；它们的当前重建完整性需要按第7节验证，不能作为已经验证可用的承诺。

体验版本必须使用正式交付记录中的`experience_launcher`、`frontend_directory`及制品摘要，并核对实际运行进程。字段为null表示尚未提供。功能启动脚本依赖对应制品和资料目录；存在脚本不能证明具备启动条件。README中的通用命令不能替代指定候选的启动说明。

配置只记录文件位置、变量名称和有效状态。不得输出、提交或复制秘密值；凭据、本地SQLite和用户资料继续保留在受保护目录。生成中间结果使用项目内已忽略目录，禁止使用`/tmp`。

## 4. 开源与模型职责

固定基础为nanobot v0.3.5，commit `1bb712d3488915ca4ed9ccc1a93067ff722f5ab9`；使用位置见 [选型验证](选型验证.md) 与 [application.py](../validation/application.py)。复用AgentLoop、Nanobot、SessionManager、CronService、WebSocket、ClientProvider及原生会话能力。业务权限、来源版本、计算、本人确认和业务持久化由项目扩展承担。

新增能力前检查上游正式扩展入口及本项目现有实现。已有能力通过同一运行与认证体系接入；避免重复实现会话、调度、工具循环和公共界面。必要扩展明确生产者、消费者、状态所有者及实际接入位置。

产品模式当前通过FeatureProvider选择业务Provider，会话采用ConversationSimulatedProvider。显式模拟能力与真实模型调用分别记录；模拟流程通过不能证明真实模型质量，选型阶段的真实模型证据仅适用于其原版本和范围。没有新增真实外部请求授权时不得自行切换。

## 5. 每次开始工作的检查

1. 完整读取本规范，检查当前目录、分支、HEAD和未提交内容。
2. 从唯一状态读取活动任务和工单；只读取该任务相关PRD、设计、接口与主记录。按需检索 [开发索引](development/index.md)，无需重复读取全部聊天和报告。
3. 核对用户最新反馈、允许修改路径、共享文件归属、已满足依赖和待确认动作。识别需求、实现、证据各自的版本。
4. 在当前任务主记录注明任务ID、采用源码、目标用户结果、设计页面、允许范围和验收条件；已有相同记录直接更新，不另建重复任务。
5. 继续已有工作时重新读取当前文件。完整需求和未完成项保留，已通过且依赖未变的证据按其实际范围复用。

文档任务、只读分析等局部工作按用户范围执行；不得因本清单自动运行产品、创建聊天、恢复自动化或扩大修改范围。

## 6. 协作与完整交付

当前活动任务覆盖全部前端。领域、Agent、界面和验证按真实依赖组织，执行顺序遵守本次前端优先要求；公共Shell、认证、路由、构建与正式状态由本次主执行者负责。

每项接口交接包含字段、Schema、错误语义、版本、源码提交及接收检查。接收者验证实际调用路径，不能仅根据文件存在登记接入。公共集成负责人对最终可运行版本负责。

| 完成维度 | 必要结果 |
|---|---|
| 业务 | 当前工单全部必要FR/BR/AC具有实际行为；工具、页面、保存与重读连通，本人决定由合法身份执行 |
| UI | 对照原页面实际加载结果核查区域、比例、信息层级、字段、操作、尺寸、响应式与交互；颜色或控件存在不能单独证明符合设计 |
| 状态与异常 | 覆盖当前行为的加载、空数据、失败、权限、取消、来源变化及未知结果恢复，证据对应明确触发条件 |
| 公共体验 | 当前页面与原生会话、Settings、共享Dialog保持一致；导航、返回、刷新及必要上下文可连续使用 |
| 可重建与启动 | 从所交付源码及锁定依赖生成完整制品，应用必要补丁，不依赖开发目录的额外手工文件；指定入口启动相同版本 |
| 证据 | 源码commit及必要未提交说明、制品摘要、命令、环境、实际结果与限制可核查；更新代码后复核受影响证据 |
| 用户验收 | 开发完成、视觉未验证、用户待验收分别登记；只有用户实际确认才能改变用户验收结果 |

执行与改动及已知风险相关的检查。没有新修改或未解决疑点时不重复全量检查；确定缺陷仍须修复并复验。声明范围不能超过证据范围，也不能删除未通过检查以取得完成结果。

交付同时提供功能名称、版本、制品、启动入口、连续操作步骤及已知限制。提交代码与切换用户运行版本分别记录；不得让用户依据新版本说明检查另一个版本。保护运行中的用户实例，需要新验证时使用独立数据与端口。

## 8. 文档维护与交接提示

规范只维护当前有效规则和来源。改变需求时更新对应PRD与工单；改变实现或运行方式时更新相关设计、主记录和启动说明。索引负责检索，唯一状态负责进度，历史结果保留原适用范围。不得通过文案调整关闭业务任务。

每次交接提示包含：完整阅读本规范；读取唯一状态中的活动工单；任务ID与用户结果；工作目录及修改范围；源码与制品依据；必要依赖；主记录位置；完成条件；未完成工作和具体阻碍。继承授权与用户限制，避免复制整套历史过程。

当前阶段参考文件中的“当前”“下一项”“继续监督”等描述，仅在与本规范列出的唯一来源及最新用户指令一致时具有执行效力。定时监督保持停止，恢复需要用户明确要求。
