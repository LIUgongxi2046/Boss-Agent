## 本轮凭据处理

本轮用户提供了 DeepSeek 凭据附件。本次只在当前私有会话核对**格式**，未将密钥值写入代码、Markdown 文档、GitHub Actions、仓库数据、模型请求日志或回复。附件本身也不作为 GitHub 文件上传。

本机使用 `scripts/configure_local_deepseek.py` 从项目根目录已有的 `boss agent.md` 读取；若凭据保存在其他本机路径，允许通过 `--source "/本机路径/boss agent.md"` 明确指定**文件路径**，绝不将密钥字符串放入命令参数。脚本写入 Git 忽略的私有文件 `boss agent.md`（0600）和 `validation/connection.json`（0600），后者仅含凭据引用、固定 DeepSeek 地址和模型标识。

本机配置示例：

```bash
python3 scripts/configure_local_deepseek.py
# 或：python3 scripts/configure_local_deepseek.py --source "/本机下载目录/boss agent.md"
cd validation && uv sync --locked && cd ..
validation/.venv/bin/python scripts/check_local_deepseek.py
```

真实 API 检查请求只包含一个无个人数据的简短探针，调用可能产生少量费用。成功后在本地被 Git 忽略的 `validation/.work/local-deepseek-health.json` 保存 response_id、finish_reason 和实际用量，不保存 Key 或输出正文。失败只记录异常类型，不伪造响应成功。**此命令尚未在开发者 Mac 实际执行。**

运行中的本机研发软件可继续使用：

```bash
bash scripts/run_boss_local.sh
# 另一个本机终端，执行只读真实会话 + 模拟经营查询联调：
validation/.venv/bin/python scripts/check_local_boss_agent.py
```

后者经已认证 nanobot WebUI/WS 调用一条只读模拟经营分析任务，并检查业务资料、服务端查询和真实模型会话结果。它不尝试给真实人员发送消息、提交审批或更新老板业务终态。成功与失败只记录受限技术元信息，文件位置为 `validation/.work/local-agent-smoke.json`；当前还没有该检查在 macOS Intel 设备上的执行回执。

## 隐私与隔离

- `validation/connection.py` 的 `RecordedProvider(redact_payload=True)` 仅在桌面产品模式保存请求 SHA-256、请求量、型号、响应 ID、Token 和 HTTP 状态；不保存原始 Prompt、原始工具参数、完整错误正文或模型返回正文。旧日志载入时也重新脱敏。
- `validation/safe_diagnostics.py` 的 `RedactedEventList` 只保留工具动作类别、对象 ID、状态、用量及错误存在性；T02 历史选型证据流程不改变。
- `validation/application.py` 在 `BOSS_PRODUCT_UI=1` 时将模型/工具诊断放入受限的 `validation/.work/application/diagnostics/`，Electron 主进程日志放入 `validation/.work/desktop/diagnostics/`；原始 T02 验证目录不再接收产品流量。
- `validation/boss_page_api.py` 实现 BOSS-only `GET /api/boss/ui/model-health` 和 MAINTAINER-only `GET /api/boss/ui/model-usage`；两个接口均返回脱敏元信息，费用覆盖未知时为 null。
- F24（老板运行详情）与 A15（维护运行记录）只展示实际观察的回执；未观察到响应明确显示未知。72 页整体追踪见 `specs/page-service-map.json`，当前 13 页部分实现、59 页仍为设计占位。
