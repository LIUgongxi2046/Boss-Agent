## 当前实现

`boss_prompt_config.obj` 的 namespace 默认保持 `ui-check`；Runtime 选择与记录传递当前执行空间。`active_runtime_prompts` 使用一致的读取事务，检查已启用指针、草稿版本、静态校验、来源访问范围、来源版本与撤销状态。旧接口 `record_runtime_context_load` 重新查询当前有效集合后记录匹配内容。

新增 `load_runtime_prompts(store, namespace="ui-check")`，在同一 `BEGIN IMMEDIATE` 内选择有效 Prompt 并记录元信息，返回本次有效集合。计数只证明上下文提供器读取，`model_completion_verified` 始终为 false。审计不保存正文。停用、来源撤销、来源更新后不增加旧配置计数。没有新增业务授权或调度来源。

新增 `boss_admin_config.memory_technical_status(store, role, namespace="ui-check")`，仅 MAINTAINER 可用。结果包含 `projection`、`namespace`、`checked_at`、`memory` 的 identifier/版本/确认状态/有效期、`future_context_eligible`、`future_turn_policy`、`deletion_propagation`、`derived_memory_index` 与隐私及验证边界。当前实现无独立个人记忆检索索引，`derived_memory_index=NOT_USED`；模型采用与物理擦除保持未验证。函数仅查询当前库，不修改本人内容。

拒绝路径：未认证 401，BOSS 或联系人 403，失效执行空间沿用 Store.active 的 409。来源撤销及配置变更通过重新读取处理。业务结果及幂等回执维持既有服务定义。
