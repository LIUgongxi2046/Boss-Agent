> 日期：2026-10-22。状态：**开发切片已入库；T11/T18 正式验收未完成**。依据 PRD V1.2.0、Desktop v6 和 HLD。用户本轮已明确授权开始开发，原 D19 对代码开发的暂停要求随本轮授权解除；业务与安全边界不变。

## 1. 交付范围

本批次并不是把 72 张 HTML 作为最终产品窗口，而是在固定开源框架 nanobot v0.3.5 的已认证 WebUI/Shell 中接入 `BossDesktop`。通过脚本 `scripts/prepare_boss_webui.py` 下载固定上游源码（校验 commit 1bb712d3488915ca4ed9ccc1a93067ff722f5ab9），复制 v6 页元数据、品牌图片、大鹏动效和 React/CSS，精确改造上游 Shell。上游源码只在 `.work/product/nanobot` 私有工作目录修改；仓库存放 Overlay 与可复现构建步骤。

本批次重点：F01 今日工作、N02 聊天入口、N03/F03 经营查询、N04 会议资料、N05/F06 任务查询、D01 来源原文、A08 维护元信息，并保留 72 页按身份可搜索的导航。其余页面明确显示“待实现”，不让尚未连接的按钮假装发送、保存、审批成功。

真实业务投影位于 `validation/boss_page_api.py`，通过现有 `RoleChannel` 的 API Token 和服务端身份检查承接。它直接读取同一 `ControlStore`，经营查询调用真实 `Store.invoke("query_metrics", ...)`、保留 Decimal 精度、Schema、资料版本、来源和模拟标志；没有重新实现一套前端数字计算。业务页面不能读取维护者不应获知的内容，维护者只获得技术元信息。老板提交自然语言由 nanobot 原生 `onStartAutomationChat` 创建/进入已认证真实会话，后续模型调用、工具执行和持久化由上游负责。

`BOSS_PRODUCT_UI=1` 才启用新构建 WebUI；无该变量时原 T02 选型验证入口保持不变。新增 Python 六组业务/权限单测和 GitHub Actions 前端编译任务。

## 2. 本机 Mac 开发执行

要求 Git、Node 24、Python 3.12、uv、能够下载固定上游依赖的网络，以及**本机服务端** DeepSeek 密钥引用。不要将密钥放入前端、日志或 Git。

```bash
git clone https://github.com/LIUgongxi2046/Boss-Agent.git
cd Boss-Agent
python3 scripts/prepare_boss_webui.py --build
cd validation
uv sync --locked
cd ..
npm --prefix validation/desktop ci
# 检查 validation/connection.json 的 credential_file，指向本机获准且权限受限的密钥文件
bash scripts/run_boss_local.sh
```

本地启动后使用 `validation/.work/application/access.json` 中创建的 BOSS/MAINTAINER 凭据进入 nanobot 认证页；不要上传这个文件。Demo 监听 127.0.0.1。当前 Electron 仍为研发宿主，引用本地 Python 源码，**尚非 T25 正式可分发 .app**。

可以先在开发环境运行：

```bash
python -m pytest -q app/tests/test_boss_page_api.py
python -m compileall -q validation/boss_page_api.py validation/role_channel.py validation/application.py
python3 scripts/prepare_boss_webui.py --build
```
