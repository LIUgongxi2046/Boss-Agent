# U2-02 运行与数据实施准备

`AgentRunObjectScope` 为本人明确选择的业务对象保存不可变范围，包含对象类型、编号、版本、内容摘要、目标版本及来源范围摘要。支持任务、指标详情、事件、出行计划和当前本人目标；读取时重新核查业务对象、来源与记忆。`GET /api/v2/runs/{run_id}/object-scope/candidates` 返回当前运行来源范围内可读取的候选正文、对象版本、摘要及来源，供本人逐项选择；不会自动选择。`POST /api/v2/runs/{run_id}/object-scope` 保存选择，`GET /api/v2/runs/{run_id}/object-scope/requests/{request_key}` 在重新核查目标、来源和对象版本后读取原回执。接口要求本人认证和当前会话订阅；迁移 `upgrade2_run_object_scope_001` 需要明确安装，产品服务在迁移完整时装配该能力。前端还需提供对象选择。本人认证后的保存、重试及回执读取，出行计划和本人目标的成功选择均为 NOT_RUN。

`GET /api/v2/runs/{run_id}/object-scope/meeting-candidates/{meeting_id}` 为当前会议提供 `meeting_context` 候选，包含会议、参会人员、领域简报、关联任务、事件、出行、人员简报及其任务和反馈、指标明细、指标定义、期间、有效指标配置和本人目标。候选按现有领域读取和明确关联构造，逐项核查当前本人、执行空间、来源及版本；任何必要来源或关联不可核查时拒绝。指标配置记录包含实际版本与内容摘要；未采用配置的指标保留空值。本人须在界面查看候选并通过对象选择接口明确提交该对象的 `entity_type`、`object_id`、`version`、`sha256`，不会自动选择。候选中的完整成员及内容共同计算摘要，成员、内容、配置或会议版本变化使原选择失效。

候选响应增加 `selection_allowed` 和 `unavailable_reasons`，分别说明当前目标可否新增选择及运行状态、取消或已有选择造成的限制；未获当前来源范围许可的对象不会出现在候选中。出行计划的当前或待确认交通依据由领域投影检查，来源未选择时该计划不进入候选。

运行创建 Schema 支持可选 `method_selection`，字段为 `sop_id`、`version`、`content_sha256`。`AgentRunMethodSelection` 使用真实方法目录和运行工具名称核查方法启用、版本、摘要与依赖，并在同一数据库事务保存方法名称、版本、摘要、初始目标版本、目标摘要和会话范围摘要。该记录表示 `SELECTED`，方法实际采用仍须核查运行中的方法读取事件；服务不从目标文字推断本人选择。普通运行保留现有创建接口，会议执行须由产品入口显式要求并核查方法选择。

U2-03 装配需要安装独立迁移 `upgrade2_run_method_selection_001` 和 `upgrade2_run_method_reselection_001`，以同一运行数据库、`RunScopeService`、`BossSkillCatalog` 和 `BossSkillDrafts` 构造 `AgentRunMethodSelection`，再通过 `RunBroker(..., method_selection=service)` 接收显式选择。创建事务要求方法配置锁；未装配服务时带方法选择的创建返回 503，已有事务入口拒绝绕过配置锁。`RunBroker.read` 对当前目标有选择记录的运行返回 `method_selection`，包含 `sop_id`、`name`、`version`、`content_sha256`、`goal_revision` 和 `state=SELECTED`；身份、会话和当前来源检查继续适用。运行启动和会议上下文装配须调用 `service.require_current(sink)`，并与实际方法读取结果比较；缺少选择、版本变化、依赖缺少、范围变化或目标补充尚未采用时拒绝。

## 4. 租约、事件与恢复

租约接口建议为 `acquire_lease(run_id, expected_revision, owner, ttl)`、`renew_lease(run_id, owner, epoch, ttl)`、`release_lease(run_id, owner, epoch)`。ttl必须为配置中的有限正值。取得租约用 `BEGIN IMMEDIATE` 核查状态、旧租约期限与revision，更新owner、expiry并递增epoch；每次工具授权、领域提交和Bridge事件接收都再次核查owner、epoch、expiry。只依赖hook不能保证此边界。

外部模型请求不持有SQLite事务。正式本地业务写入在事务内检查当前epoch、cancel标识、授权、来源和对象版本，随后执行领域动作并保存回执。取消和写入由同一数据库的事务先后顺序确定；已提交写入重读展示，不能因后到取消抹去事实。文件或其他进程中的在途动作单独记录并查询原执行编号。

每个会话的目标补充串行接收；建议限制同一会话最多一个未终止主运行，子任务使用parent_run_id并继承资料范围。输入接收后持久保存，Bridge依input_seq顺序采用。来源变更后旧输出不能满足新goal_revision；成功判定要求 `applied_goal_revision == goal_revision` 且必要成果和业务回执全部核查通过。

Bridge重连使用稳定origin_event_id；服务端seq仅由数据库分配，不采用Bridge自报seq。状态转换与事件写入同事务；事件提交后才推送，推送失败仍可重放。快照返回last_event_seq，客户端以该序号继续订阅；订阅期间再次查询持久事件，消除快照与订阅之间的遗漏。客户端按run_id、seq去重。终态拒绝状态改写；迟到的业务事实进入单独审计核查，不能丢弃正式回执。

引擎失联、租约失效或产品异常退出使执行归属失效；恢复读取租约和回执，运行进入INTERRUPTED或RECONCILING。启动恢复仅进行查询和投影，不自动继续未知写入。`cancel_requested_at` 始终保留，具有该标识的运行禁止继续新动作。已取消运行只有全部在途已查明才进入CANCELED。

进程重启的实例凭据重新生成，旧实例凭据拒绝。产品退出或认证撤销同样阻止工具继续执行；浏览器连接断开仅终止订阅，不能单凭连接断开取消持久运行。认证有效期、实例租约和用户取消分别处理。

## 12. 原请求回执与允许操作

## 18. USAGE_RECORDED 事件保存、重放与累计语义（2026-10-31）

`RunBoundBudgetStore.record_usage_snapshot` 在单一 `BEGIN IMMEDIATE` 事务内完成租约、根运行和授权检查，读取整个 `root_run_id` 的累计请求，递增持久化的 `hermes_usage_revisions.revision`，并通过 `RunStore.append_event_in_transaction` 写入 `USAGE_RECORDED`。事件写入失败时版本和事件一起回滚；重复调用在通过同样的租约、根运行、授权和迁移检查后返回已有事件，不分配新版本。`snapshot_revision` 为持久化整数，`snapshot_final` 固定为 `false`，`total_tokens` 表示当前快照的已知总量，不表示所有后代退出后的最终消耗。未知消耗和费用保持 `null` 与 `UNKNOWN`。多个累计快照不能相加。

- 两个请求并发完成后，两个并发快照调用返回同一事件；只有一个事件和一个版本 1，数据库重开后版本仍为 1。
- 旧格式 `{requests_used,total_tokens}` 事件仍通过 Schema 并可重放；消费函数对只有旧事件的数据返回 `null`，不推断顺序。
