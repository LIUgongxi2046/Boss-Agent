## 1. 物理存储

| 文件与物理表 | 字段与类型 | 约束、索引与职责 |
|---|---|---|
| `business.sqlite` / `objects` | `namespace TEXT`、`kind TEXT`、`id TEXT`、`body TEXT NOT NULL` | 复合主键 `(namespace,kind,id)`；`body` 使用 JSON 保存领域对象 |
| `business.sqlite` / `spaces` | `namespace TEXT PRIMARY KEY`、`active INTEGER NOT NULL`、`snapshot TEXT NOT NULL` | 执行空间、有效标识、初始快照摘要 |
| `business.sqlite` / `idempotency` | `namespace TEXT`、`operation TEXT`、`key TEXT`、`digest TEXT`、`result TEXT` | 复合主键 `(namespace,operation,key)`；保存参数摘要与原结果 |
| `business.sqlite` / `audit` | `id INTEGER PRIMARY KEY`、`namespace TEXT`、`operation TEXT`、`input TEXT`、`output TEXT`、`created_at TEXT` | 领域审计；普通技术记录应采用标识和摘要 |
| `business.sqlite` / `knowledge` | FTS5：`namespace UNINDEXED`、`source_id UNINDEXED`、`content` | 初始化建立的全文索引；用于既有查询路径 |
| `business.sqlite` / `knowledge_text` | FTS5：`namespace UNINDEXED`、`source_id UNINDEXED`、`content`；`tokenize='trigram'` | 当前中文片段全文索引，`document` 插入、更新、删除触发器维护内容 |
| `accounts/accounts.sqlite` / `accounts` | `username TEXT PRIMARY KEY`、`password_hash BLOB NOT NULL`、`role TEXT NOT NULL` | `CHECK(role IN ('BOSS','MAINTAINER'))`；bcrypt 摘要，文件权限0600 |

物理定义来自 `business.Store.__init__`、`initialize_in_transaction` 和 `boss_account_auth.provision_accounts`。SQLite 业务连接设置10秒等待、WAL 与 `foreign_keys=ON`；JSON 对象间关系由领域服务检查。列的 NOT NULL 约束以表中声明为准。Session、工作目录与 Cron 数据由原生 nanobot 管理，其位置见[运行环境](运行环境.md)。

## 2. 业务实体与当前使用方

| `objects.kind` 或字段 | 含义与正式字段来源 | 当前使用方 |
|---|---|---|
| `initial` / `snapshot` | `owner_id`、`dataset_id`、`dataset_version`、`boss_profile`、`contacts`、`periods`、明细及获准初始资料 | 当前空间身份、统一业务资料与领域服务 |
| `clock` / `current` | `at`、`version`；业务时间与真实运行时间分别记录 | 今日工作、期限、会议、模拟事件 |
| `document` | `source_id`、`version`、`content`、`source_type`、`access_scope`、作者、发布时间、有效期及撤销标识 | 原文、来源有效性、知识索引与 Agent 工具 |
| `document.sector_facts`、`sector_page`、`sector_scope` | 专题数值、单位、期间、明细和适用范围；生成器见 `boss_comprehensive_simulation._sectors` 的实际定义 | `BossSectorAPI`、`BusinessOverviewAPI.topic_in_transaction`、会议准备 |
| `document_history` | 更新前的文档版本，存储编号为 `source_id:version` | 历史来源与版本核查；历史存在不代表当前可采用 |
| `query`、`query_source_binding` | 查询结果、明细、正式范围与来源版本/摘要绑定 | BI 查询、证据读取、原请求恢复 |
| `task`、`feedback`、`assignment_source_binding` | `task_id`、`version`、`status`、`coordinator_id`、`due_at`、来源、反馈和结果证据版本 | 任务与承诺、专题关联、本人完成决定 |
| `self_commitment` | 本人承诺、期限、状态和当前来源 | 本人承诺列表、今日事项与提醒 |
| `meeting`、`meeting_draft`、`minutes` | 当前会议、独立草稿与纪要；字段见 [基础接口规范](../specs/openapi.yaml) 和对应领域服务 | 会议资料、会前准备、纪要确认与关联交办 |
| `authorization` | 本人、动作、对象、版本、完整参数、有效期和撤销状态 | 写入前服务端核查，持续采用按当前状态及撤销检查 |
| `runtime_run` | `run_id`、运行状态、模型请求、工具结果、配置引用、结束原因及流式观察 | Agent 执行追溯；Schema 见 [运行记录定义](../specs/runtime-records.schema.json) |
| `sector_pack` / `current`、`comprehensive_simulation` | 专题资料版本及仿真生成标记；生成结果含 `public_baseline_sha256` | 重复生成检查与统一资料版本 |

实体字段的必需、可空和枚举规则采用对应 Schema；本表未把所有 JSON 字段声明为必需字段。对象版本通常采用十进制字符串；金额和确定性指标保留 Decimal 字符串与原始单位，缺少值保持 null。`namespace` 与数据集版本分别检查，客户端不能指定权限归属。

## 3. 经营会话实体

| `kind` | 编号或关键字段 | 约束与关系 |
|---|---|---|
| `conversation_business_store` | `instance`；`store_reference` | 当前资料实例身份，避免跨实例采用准备记录 |
| `conversation_business_preparation` | `preparation_id`、`client_request_id`、`request_sha256`、`preparation_sha256`、`applied_scope`、`scope_sha256`、`topic_reference`、`topic_sha256`、`snapshot_sha256`、`source_references`、`business_at`、`context` | 服务端绑定 owner、namespace、dataset/version；状态为 `PREPARED` 或 `BOUND` |
| `conversation_business_binding` | 原生 `session_id` 作为存储编号；保存 `chat_id`、`native_session_created_at`、准备编号及摘要 | 必须关联真实会话；已有运行或其他事项绑定时拒绝占用 |

公开字段分别采用 [EntryPreparation](../specs/business-overview.schema.json)、`EntryContext`、`EntryReceipt`。持久对象还保存服务端身份和摘要字段，不能直接把公开投影作为完整数据库对象写回。读取原回执不会确认当前资格；再次采用时重新比较对象、资料与摘要。

## 4. 知识与来源元数据

当前检索使用 SQLite FTS5；本次核查没有独立 VectorDB Collection、embedding 维度或通用 Chunking 元数据的实现依据。当前字段映射如下：

| 元数据 | 使用与限制 |
|---|---|
| `namespace` | SQLite 对象及 FTS 行的空间范围，全文查询还需要显式校验 |
| `source_id`、`version` | 文档身份与采用版本 |
| `access_scope` | 当前老板的来源读取资格 |
| `source_type` | 区分 `SIMULATED`、`PUBLIC_SOURCE` 等来源属性；执行记录单独使用 `RUNTIME_RECORD` |
| `published_at`、`observed_at`、`valid_from`、`valid_until`、`withdrawn` | 日期与当前有效状态 |
| `content_sha256`、`representation_sha256` 或业务绑定中的摘要 | 按对应投影核查完整内容或表现形式，字段名称采用各自 Schema |
| `sector_page`、`sector_scope`、`sector_facts` | 专题、法人/区域和专业单位范围 |

FTS 命中需要继续经过来源访问及有效性检查。触发器清理撤销文档索引；有效期、类型和跨对象引用仍由领域代码核查。公开年度报告的期间和单位保持原义，当前模拟月度记录由生成器单独标记；财报数值核查记录见[仿真任务](development/SIMULATION-20261028.md)。

## 5. 备份、迁移与未完成范围

运行中的 WAL 数据库不能只复制主文件作为一致备份。独立模拟快照使用 SQLite 原生备份并核查完整性和摘要；当前范围仅覆盖模拟业务 SQLite，恢复预检保持 `BLOCKED`。正式完整备份、来源与删除历史、文件一致性及恢复读取仍需验证，不应对用户数据库执行恢复。

本次没有执行数据库迁移、资料初始化、备份或恢复。数据字典核查不能证明完整产品数据生命周期通过。业务操作与恢复要求见[操作手册](操作手册.md)，完整未完成项见[唯一正式状态](../specs/feature-delivery.json)及相应任务主记录。
