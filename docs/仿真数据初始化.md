# 仿真数据初始化

初始化入口为`scripts/prepare_comprehensive_simulation.py`，业务生成器为`validation/boss_comprehensive_simulation.py`，公开经营基准为`specs/public-business-baseline.json`。三者随源码提交，生成后的本机数据库、密码、密钥、会话和运行回答保留在Git忽略目录。

## 环境与资料

使用Python 3.12、uv、Node.js 24和Git。在仓库根目录准备锁定依赖：

```bash
cd validation
uv sync --locked
cd ..
npm --prefix validation/desktop ci
```

首次初始化新目录：

```bash
validation/.venv/bin/python scripts/prepare_comprehensive_simulation.py \
  --directory validation/.work/comprehensive-simulation-20261028 \
  --business-at 2026-10-28T09:00:00+08:00 \
  --create --initialize-accounts
```

`--business-at`必须包含时区，用于首次生成的业务日期、月份与关联期限。目录必须位于`validation/.work`的直接子目录。`--create`拒绝覆盖已有业务数据库；账号采用独立的`boss`和`maintainer`身份，各自生成随机密码，账号数据库保存bcrypt摘要，凭据保存在该目录的`accounts/credentials.json`，权限为0600。脚本输出接口数量、管理员资料规模和账号创建状态，不输出密码，不登录产品，不发送模型请求。

生成资料包括14位联系人、13个专题及用途、12项交办、3项本人承诺、4场会议、4项申请、来源资料、消息、行程、反馈和事件。十四项模拟接口均有记录，管理员页面从同一业务空间读取配置及资料。真实模型运行、正式评测和实际用户操作由后续运行产生，初始化不生成此类成功记录。

已有业务资料补充同版本生成内容时，使用：

```bash
validation/.venv/bin/python scripts/prepare_comprehensive_simulation.py \
  --directory validation/.work/comprehensive-simulation-20261028 \
  --business-at 2026-10-28T09:00:00+08:00 \
  --initialize-accounts
```

重复执行保留当前版本资料、本人已保存的操作、运行配置、账号及密码。该命令不推进现有业务时钟；时钟操作使用管理端的正式流程。已有账号文件不完整时直接报告错误，不重新生成密码。初始化无需其他机器或已有实例的数据库。

## 构建与启动

模型凭据由使用者在本机提供，通过`scripts/configure_local_deepseek.py`配置；仅传入本机文件路径，密钥不进入命令参数或仓库：

```bash
python3 scripts/configure_local_deepseek.py --source /本机目录/模型凭据.md
validation/.venv/bin/python scripts/prepare_boss_webui.py
cd .work/product/nanobot/webui
npm exec -- tsc -p tsconfig.build.json
npm exec -- vite build --outDir ../../../simulation-20261028/admin-dist
cd ../../../..
bash scripts/run_comprehensive_simulation_local.sh --desktop
```

启动器使用上述固定资料目录与前端目录，端口为9081、9082和18892。桌面与WebUI共用这些端口；已有同一实例运行时继续使用当前窗口。只启动WebUI时执行`bash scripts/run_comprehensive_simulation_local.sh`，访问本机9082端口。模型连接与实际运行采用管理端当前有效配置；新机器的连接验证和模型请求由使用者实际执行，不继承其他机器的验证结论。

首次登录使用本机凭据文件中的对应身份。管理员A03查看业务资料，A04查看任务及反馈，A05查看当前运行配置，A13查看事件与期限，A16查看已有运行；Boss端使用同一空间的五项主菜单。普通初始化不改变已有验收实例，当前产品验收状态继续采用`specs/feature-delivery.json`。

## 公开基准与验证

公开经营基准保留原始年度、金额单位、合并范围和来源地址；月度、人物、客户、任务与事件采用明确的模拟记录，产品企业名称为丰泽农牧集团。生成脚本直接读取仓库中的基准文件，离线生成业务资料。需要重新核查原始公开报告时，执行`validation/.venv/bin/python scripts/verify_public_business_baseline.py`，该命令访问公开报告并在忽略目录保存摘要结果。
