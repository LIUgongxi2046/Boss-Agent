## 身份、来源与错误

运行与本人业务接口使用现有产品认证；调用方不能以角色请求头替代身份，不能提交主体或授权字段取得权限。运行还要求当前本人连接订阅相应会话，服务检查会话与所选来源范围。相应代码见 [agent_run_api.py](../validation/agent_run_api.py)、[role_channel.py](../validation/role_channel.py) 和 [agent_run_scope.py](../validation/agent_run_scope.py)。同源服务核查 `Host`、`Origin` 及 `Sec-Fetch-Site`；本人决定、计划和历史关联写入要求匹配的 `Origin`。

独立 HTTP 检查覆盖未认证、角色请求头、无效凭据与跨来源请求，分别得到401或403，重复请求未改变独立业务数据库；结果见 [U2-09](development/U2-09.md)。当前运行创建的 `require_product_engine_ready` 和成果读取的 `require_artifact_read_boundary` 返回503 `SERVICE_NOT_READY`。这两项保护函数已有直接调用证据；合法本人会话下的 HTTP 响应尚未验证。

运行接口的请求和响应字段以 [agent-runs.schema.json](../specs/agent-runs.schema.json)、[agent-events.schema.json](../specs/agent-events.schema.json) 为准，意图字段以 [agent-intents.schema.json](../specs/agent-intents.schema.json) 为准。[OpenAPI](../specs/agent-runtime.openapi.yaml) 描述运行、运行恢复、本人意图、成果读取、来源历史、计划执行、历史关联及方法候选路由。内部模拟数据库恢复服务没有装配为上述产品同源路由。部分运行错误使用 `code`、`message`、`run_id`、`trace_id`、`failed_step`、`completed_refs`、`recovery_action`；其他接口可能返回文本错误，不能将统一错误格式视为全部接口的当前行为。详细设计中的状态码要求仍需逐项验证。

F05 与 F07 页面在 token 变化时重新建立，页面内未保存的条目、正文、原文位置与决定草稿随组件卸载丢失；存在未保存编辑时页面显示提示，说明内容已经清除、当前不能证明同一认证会话且没有自动恢复，提示可以关闭。身份读取只在工作区挂载和手动重试时执行，不随 token 更新重新读取；显式退出会卸载工作区。身份接口返回的 `owner_id` 当前固定为 `boss-1`，执行范围来自服务环境，没有可区分的真人身份或认证会话编号；该结果不能作为本人身份或同一会话的证明。跨认证恢复未保存草稿为 `NOT_RUN`，当前不会在身份核查前自动清除其他页面的未保存标识。

运行快照包含 `status`、`revision`、`goal_revision`、`applied_goal_revision`、`last_event_seq`、`cancel_requested_at` 和 `allowed_actions`。允许动作与事件结构由服务和 Schema 决定；事件缺号时需要从连续游标重新读取。`cancel_requested_at` 非空时，N02 显示取消请求记录时间；`CANCEL_REQUESTED` 说明在途动作仍在核查，`RECONCILING` 说明正在核查原业务动作结果且不能重复提交，`CANCELED` 说明取消前已经完成的业务动作继续保留。加载、断开和读取错误期间不显示旧取消说明。补充输入回执显示输入编号、输入序号和目标版本，并与当前快照比较：相同为当前目标版本，低于当前为历史目标版本，高于当前要求重新读取运行。当前客户端实现与限制见 [U2-07](development/U2-07.md)，运行租约、预算和事件的独立测试见 [U2-02](development/U2-02.md)。来源清理待处理、失败或已经撤销时，相关运行不能继续采用该来源；完整产品传播仍需验证。

对象范围路由要求本人认证、当前会话订阅、运行所属范围及当前来源和记忆核查；运行编号须为规范 UUID，查询参数不受支持。产品服务只有在 `upgrade2_run_object_scope_001` 迁移可核查时装配该服务，未装配返回 `SERVICE_NOT_READY`。五类目录为 `task`、`metric_detail`、`event`、`travel_plan`、`owner_goals_active`；指定会议入口提供 `meeting_context`，核查会议、成员和关联资料。候选对象提供 `entity_type`、`object_id`、`version`、`sha256`、`source_refs`、`data`；来源引用包含 `source_id`、`version`、`sha256`。对象选择请求的 `objects` 含一至100项明确对象引用，每项仅包含类型、编号、版本及摘要；不能重复同一类型和编号。回执包含运行、目标版本、请求编号及核查后的对象与来源。当前目标的首次选择要求 `QUEUED` 或 `WAITING_INPUT`；`RUNNING` 仅能核查相同原请求。状态、版本或请求冲突返回 409；来源不在范围内可能返回 403。请求结果未知时保留原编号并查询原回执；回执查询重新核查对象、来源和目标。对象选择只限定运行读取范围，不授予业务写入权限。N02 提供五类对象及指定会议范围读取和明确选择；会议编号由本人输入，页面展示会议、参会人员、关联对象、来源及允许状态。本人认证后的读取、选择和回执仍为 `NOT_RUN`。

两个候选响应提供 `selection_allowed` 和 `unavailable_reasons`；原因可包含 `RUN_CANCELED`、`RUN_STATE_UNAVAILABLE`、`GOAL_ALREADY_SELECTED`。这些字段说明当前运行的选择条件；服务筛除不可读取或来源不符的对象，未提供被筛除对象的逐项原因。候选读取筛除附加来源未获选择的出行计划；对象提交与原回执查询重新核查当前来源。指定会议成功读取当前返回一项候选，权限或资料条件不符时返回错误。N02 在对象选择或回执返回 401、403、404、409、410 时隐藏已展示的对象和回执，保留原请求；会议候选读取返回 401、403、410 时隐藏已展示的对象。页面提供重新核查范围和查询原回执入口。

完成检查由内部 `POST /internal/v1/events` 接收 `RUN_FINISHED` 时，在存在运行授权和上下文服务的条件下触发；同一事务核查当前运行授权、租约、来源、记忆、目标输入、结果及结束事件，保存检查记录。事件接口返回已保存事件，当前没有本人产品 API 读取完成检查回执。检查结果始终为 `BLOCKED`，至少包含 `RESULT_SEMANTICS_UNVERIFIED` 与 `PROCESS_GROUP_EXIT_UNVERIFIED`；必要成果、文件预留及待处理意图还可能增加阻碍。当前调用没有传入成果文件核查服务，文件内容核查不能由此推断通过。正式引擎、本人成功路径及产品完成验收仍为 `NOT_RUN`。

快照可包含 `method_selection`：`sop_id`、`name`、`version`、`content_sha256`、`goal_revision` 和 `state`；`state` 为 `SELECTED`。符合当前条件时 `allowed_actions` 包含 `SELECT_METHOD`。方法目录返回 `run_id`、`goal_revision`、`selection_allowed` 和 `methods`；每项提供上述方法身份、`status`、`reasons`、`missing_native_tools`、`missing_runtime_tools` 和 `missing_projections`。状态为 `AVAILABLE` 或 `UNAVAILABLE`；原因包括 `DISABLED`、`METHOD_UNAVAILABLE`、`NATIVE_TOOLS_MISSING`、`RUNTIME_TOOLS_MISSING`、`PROJECTIONS_MISSING`。

三个方法路由要求有效本人会话、会话订阅以及当前来源和记忆范围；查询参数不受支持。选择适用于目标版本至少为 2、运行仍可操作、初始方法存在且当前目标尚未选择方法的情况，服务还核查配置、目标输入和方法依赖。写入请求中的 `method_selection` 包含 `sop_id`、`version`、`content_sha256`；回执包含 `run_id`、`goal_revision`、`input_id`、`request_key` 和方法投影。已有请求编号与内容一致时可返回原回执，内容冲突返回 409；回执查询仍核查当前范围。服务未装配时返回 503，错误可能为 JSON 或文本。字段结构见 [运行 Schema](../specs/agent-runs.schema.json) 和 [OpenAPI](../specs/agent-runtime.openapi.yaml)。

`WAITING_INPUT` 且等待原因是 `INPUT_REQUIRED` 时，经过事件、工具调用及目标版本核查的快照可包含 `waiting_input`，其中 `event_id`、`goal_revision`、`question` 关联当前补充问题。N02 读取连续事件并核对运行编号、事件类型、目标版本和问题正文；不一致时要求重新读取。N02 在允许选择时读取目录，核查运行编号、目标版本及方法编号唯一性，只允许选择 `AVAILABLE` 方法；提交前保存原请求编号与方法信息，结果未知时查询原回执，并核对编号、版本和摘要。本人认证后的方法选择、问题展示和连续交互仍为 `NOT_RUN`。

结果 `RESULT_RECORDED` 的 `payload` 包含 `text`、`goal_revision`、`engine_commit`、`dataset_id`、`dataset_version`、`source_pins` 和 `citations`。`citation_checks` 中的 `locator_verification` 当前为 `NOT_VERIFIED`，不能据此认定原文位置已经验证。目标补充产生新 `goal_revision`，旧结果继续属于旧版本。独立记录检查见 U2-09；正式引擎结果与本人访问仍为 `NOT_RUN`。

来源历史的运行编号及事件或成果编号需要规范 UUID，查询参数各出现一次。结果来源版本为最多32位的规范 ASCII 十进制文本；成果来源的 `version` 与 `artifact_version` 为最多16位的规范正整数文本。响应包含版本、摘要、当前版本、历史标记、标题、正文及原引用位置；位置状态为 `NOT_VERIFIED`。两条路由均核查本人身份、会话订阅和来源范围；成果来源历史读取业务数据库，其装配不开放成果文件读取。响应结构见 [结果来源 Schema](../validation/agent_source_history_schema.json) 和 [成果来源 Schema](../validation/agent_artifact_source_history_schema.json)。

恢复状态的 `allowed_actions` 当前为空，`waiting_reasons` 包含引擎边界、进程回收和预算复核等条件。三个路由均要求本人认证、会话订阅与来源范围核查；运行编号须为规范 UUID，查询参数不受支持，恢复 POST 需要匹配的 Origin。补充输入后 `WAITING_INPUT` 保持等待；新恢复请求核查运行版本、目标版本和当前状态后仍受 `SERVICE_NOT_READY` 保护。内容相同且已经保存的恢复请求可返回原回执，也可按原请求编号查询；本人认证后的读取和恢复执行仍为 `NOT_RUN`。运行恢复与模拟数据库恢复分别处理。[恢复 Schema](../validation/agent_run_resume_schema.json) 和 [U2-03](development/U2-03.md) 记录字段及限制。

恢复状态接口返回 HTTP 错误、网络不可用、读取超时或 Schema 不符合时，N02 显示对应错误并保留原运行，同时提供“重新读取继续运行条件”按钮。读取使用 `XMLHttpRequest` 的 `onload`、`onerror` 和 `ontimeout` 事件，不使用 Promise 拒绝回调、`catch` 或 `try/catch`；Schema 校验返回错误文本，不抛出异常。实际本机网络、Schema、HTTP 503 与 HTTP 401 检查见 [U2-09](development/U2-09.md)；本人认证后的成功读取与恢复仍为 `NOT_RUN`。

## 会议、纪要与交办工具

以下路径属于 Hermes 内部工具通信，使用进程凭据和运行范围核查，不能作为本人产品 API 使用。请求均为 JSON，`protocol_version` 为 `1`；写入与业务意图的 `request_key` 为8至128位 ASCII 字母、数字或 `-_.`。

| 方法与路径 | 请求字段 | 当前行为 |
|---|---|---|
| `POST /internal/v1/tools/meeting-context` | `protocol_version`、`call_id` | 返回 `result`，含会议版本及可用草稿；有效草稿包含 `confirmation_parameters` |
| `POST /internal/v1/tools/meeting-draft` | `protocol_version`、`request_key`、`params` | 保存会议草稿，返回 `draft`；字段与来源版本按领域规则核查 |
| `POST /internal/v1/tools/minutes-context` | `protocol_version`、`request_key` | 返回 `result`，包含 `meeting_id`、`meeting_version`、`minutes` 和 `assignment_context` |
| `POST /internal/v1/tools/minutes-draft` | `protocol_version`、`request_key`、`params` | 保存纪要草稿，返回 `result` 和可用的确认参数 |
| `POST /internal/v1/tools/domain-intent` | `protocol_version`、`request_key`、`action`、`params` | 生成本人决定预览；需要实际本人会话授权，未装配时返回 `INTENT_SERVICE_UNAVAILABLE` |

会议草稿 `params` 包含 `meeting_id`、`meeting_version`、`expected_version`、`purpose`、`starts_at`、`ends_at`、`timezone`、`preparation_due_at`、`participant_ids` 和 `source_refs`。纪要草稿包含 `meeting_id`、`meeting_version`、`source_id`、`source_version`、`expected_version` 和 `entries`；每项 `entries` 包含 `kind`、`text`、`source_anchor`，`kind` 取 `OPINION`、`SUGGESTION`、`DECISION`、`ASSIGNMENT_DRAFT`。完整字段及约束见 [hermes_domain_schema.py](../validation/hermes_domain_schema.py)。

业务意图的 `action` 和 `params` 如下；预览还记录目标版本、对象版本、来源摘要、影响、内容及本人决定要求。草稿保存不产生正式会议确认或交办。

| `action` | `params` |
|---|---|
| `boss.meeting.confirm` | `meeting_id`、`meeting_version`、`draft_version`、`review_sha256` |
| `boss.meeting.cancel` | `meeting_id`、`expected_version`、`reason` |
| `boss.meeting.held` | `meeting_id`、`expected_version`、`reason` |
| `boss.minutes.confirm` | `meeting_id`、`expected_version`、`source_id`、`source_version` |
| `boss.minutes.assignment.create` | `meeting_id`、`minute_version`、`entry_id`、`purpose`、`coordinator_id`、`due_at`、`timezone`、`evidence_requirements` |
| `boss.assignment.create` | `purpose`、`coordinator_id`、`due_at`、`timezone`、`evidence_requirements`、`related_meeting_id`、`related_event_ids`、`source_refs`、`content_version` |

会议和纪要草稿的 `TOOL_FINISHED` 事件包含 `goal_revision` 和 `draft_ref`；后者包含 `kind`、`object_id`、`version`、`sha256`、`domain_operation`、`domain_request_key`。草稿关联检查核对领域记录与当前来源，返回 `RECORD_PRESENT` 或 `NOT_VERIFIED`；记录存在仍需核查目标语义。独立草稿、预览及版本检查见 U2-03 与 U2-09，本人授权下的成功调用和正式引擎执行仍为 `NOT_RUN`。

本人决定请求包含 `decision`、`expected_revision`、`payload_digest` 和 `request_key`；适用会议冲突时使用 `acknowledge_conflict`。领域决定成功回执包含 `intent_id`、`status`、`revision`、`authorization_id`、`result_ref`、`action`、`goal_revision`、`business_object_id`、`business_object_version` 和 `source_refs`。当前 N02 将会议回执编号与版本传至 F04，将交办回执编号与版本传至 F06；页面重读后比较当前版本。`BUSINESS_RECEIPT` 关联检查可以报告已记录的回执，运行完成检查中的该项仍为 `NOT_VERIFIED`。本人成功决定、回执重读及连续页面操作仍为 `NOT_RUN`。

## 方法候选接口

方法候选接口通过 [hermes_skill_routes.py](../validation/hermes_skill_routes.py) 装配；本人或维护者认证后可读取候选列表。本人可查看候选正文、提交 `APPROVE` 或 `REJECT`，并按原 `client_request_id` 查询决定回执。维护者可读取维护详情、执行静态校验、使用本人授权发布，以及查询原发布状态。发布、停用、恢复和取消请求需要匹配的 `Origin`；服务检查对应角色和当前执行空间。

`POST /api/v2/skills/recover` 和 `/api/v2/skills/cancel` 需要 `client_request_id`、`sop_id`、`activation_request_id`，用于处理 `PREPARED` 方法启用记录。发布及恢复需要核查当前方法、候选、授权和工具依赖；其成功行为尚未在本人认证的产品流程中验证。这些接口处理方法启用状态；模拟数据库恢复由独立内部服务承担，当前恢复预检保持 `BLOCKED`，没有对应的正式产品恢复路由。

## 模拟资料、成果与计划

模拟资料使用明确的 `SIMULATED` 空间及资料集版本，来源读取仍检查当前空间、主体、版本和撤销状态。独立模拟资料的会议、材料及已有业务对象读取已有局部证据，见 [U2-09](development/U2-09.md)；模拟记录不能代表本人决定。没有授权时不要初始化或修改用户数据库，不要触发外部模型请求。

成果服务具备 Markdown、PDF、DOCX、XLSX、PPTX 格式处理；独立模拟资料生成并重新读取五种格式的结果见 [U2-04](development/U2-04.md) 和 U2-09。成果登记、本人读取、发布及桌面选择目录导出尚未取得合法成功路径证据。当前产品装配未指定成果工作区时安装关闭路由，认证后返回服务未就绪；指定工作区的读取路由同样保留隔离保护。

N02 的成果列表通过 `GET /api/v2/runs/{run_id}/artifacts` 读取，元信息和文件分别通过 `GET /api/v2/artifacts/{artifact_id}` 与 `/file` 读取，响应按 `validation/agent_artifact_schema.json` 核查。打开与导出要求服务提供当前允许动作，页面不根据成果状态自行推断授权；运行 Schema 的 `allowed_actions` 当前只有 `READ_EVENTS`、`ADD_INPUT`、`CANCEL` 和 `SELECT_METHOD`，因此打开与导出按钮保持不可用。当前 `validation/application.py` 没有向 `hermes_product_application` 传入 `artifact_workspace`，服务安装关闭路由；即使传入工作区，成果路由边界仍返回 503 `SERVICE_NOT_READY`。产品环境中的成果列表、文件读取与导出均为 `NOT_RUN`，开放条件属于 U2-02 与 U2-04 的服务装配和隔离核查。

计划预览、决定、绑定和原回执对应 [hermes_plan_routes.py](../validation/hermes_plan_routes.py)。计划交接清单状态保持 `DISABLED`，旧调度全局停止、唯一执行租约、本人授权及正式计划触发尚未验证，见 [U2-06](development/U2-06.md) 与 [U2-08](development/U2-08.md)。

## 迁移、会话与恢复

`AgentMigrationInventory` 在独立 SQLite 中记录业务表分组数量和摘要，并在相同版本输入变化时拒绝；其范围不覆盖全部业务表、会话文件、配置或成果文件。`AgentLegacyInventory` 核查原生会话快照与范围摘要，历史内容采用仍依赖本人认证、会话订阅和运行范围。会话文件与 SQLite 没有覆盖全部写入方的共同事务。

模拟快照仅允许项目 `.work/upgrade2-u2-08-simulated/` 下的独立数据库与目录，清单覆盖 `business_sqlite`。恢复预检当前保持 `BLOCKED`，原因包括可信删除历史完整性尚未证明；来源或记忆变化后旧检查点会被拒绝。不得将此快照视作完整产品备份，也不得据此恢复用户资料。模拟快照、历史会话和恢复证据见 [U2-08](development/U2-08.md) 与 U2-09；本人认证后的恢复、完整文件备份和实际恢复均为 `NOT_RUN`。
