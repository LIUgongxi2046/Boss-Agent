## 前端与后端

F01 的 TodayProjection 与 TodayAPI 使用 item_id、order_version、snapshot_sha256 和完整 item_ids 集合，公共入口拒绝额外查询参数。本人调整后通过实际HTTP重新读取新版本。N09 的 plan_id、expected_version、event_ids、timezone、not_before 和四项动作经同一认证WebSocket提交；暂停恢复取消及重启后状态已经实际验证。

N01/D08 使用真实 bootstrap 和 identity，入口选择不授予身份。API token过期、退出和WebSocket重新认证失败卸载受保护页面；重新认证后正式对象摘要不变。A12读取维护专用元信息，服务端拒绝外部范围参数和老板请求。以上结论只覆盖已执行路径。

全部72页面和561状态、跨页对象选择、IME、焦点/筛选/滚动恢复、长内容及完整异步状态仍需逐项语义和运行检查。当前页面映射 partial 状态保留，不能根据组件存在判定完成。

## 后端与 Agent

Runtime注册query_metrics、read_evidence、create_assignment、send_assignment、read_assignment五项业务工具和仅限当前研究的bossWorkspaceRead。写入工具的envelope、当前授权和幂等绑定由服务端提供；模型输出不能写入正式终态。公共UI mutation与模型工具覆盖分别记录。两次当前共同任务源码的SDK任务观察五工具，最终WAITING_FEEDBACK，各一条模拟消息；公共应用另外观察研究工具真实调用，任务与发件箱保持一致。指定版本的四项真实异常检查覆盖取消、超时、轮数限制及写入后模型错误，适用范围见T11。

十三类秘书 SOP 的完整运行采用、十四类模拟接口、运行记录与配置版本的完整关联、产品总时间/总Token/总费用预算及全部流式事件仍需验证。T06事件Schema 1.0.0 已定义请求回执、消息和工具活动、文字增量、片段结束、turn结束、恢复、重试和上下文压缩；固定上游字段定义与实际流、取消及恢复需逐项复验，不能据Schema存在判定协议完成。

## 事件规范接收事项

`REV01`，责任T06/W1，状态OPEN。实际命令 `validation/.venv/bin/python validation/check_runtime_events.py` 使用真实认证、DeepSeek和获准只读查询，stream_end未通过事件Schema；安全元信息见 `evidence/T09/w3-20261023/runtime-event-schema-check.json`。实际字段包含turn_phase:string和turn_seq:integer，当前ChatEvent/StreamEnd未定义这两项字段，同时禁止未声明字段。固定nanobot0.3.5的 `WebUITranscriptRecorder._annotate_turn` 会写入这两项元信息。
