alerts复用BusinessAlertsAPI.project_in_transaction，保留原事件、通知、规则版本、参与原因、已有措施、处理人、缺少字段及状态。范围只从实际生成器保存的比较期间和正式selection来源范围确定，无法证明范围时不采用；alert_scope_exclusions分别给出范围和关注条件排除数量。来源变化后保留正式历史事件元信息及NEEDS_REVIEW，facts/当前通知等正文采用资格继续由原领域决定。读取不调度、知晓、暂缓、关闭或发送。

metrics只在当前会议材料明确包含finance-note时采用BusinessOverviewAPI当前Scope的正式六指标、单位、期间、定义、精度、覆盖和来源；没有重新计算固定区域或全公司数值。没有对应指标来源时metrics=[]、metric_scope/metric_coverage=null、缺口NO_METRIC_SOURCE_IN_MEETING_MATERIALS，不生成金额。topic_missing_fields保留所选专题原有专业资料缺口，scope_application继续分别表达指标期间与专题当前状态。准备结果没有新增专业判断、会议发生决定、保存或邀请动作，也不写入meeting_brief。

独立受控工具BusinessMeetingPreparationReadTool(preparation,context_provider)，name=businessMeetingPreparationRead，严格parameters={type:object,properties:{},additionalProperties:false}。context_provider必须由当前可信服务端返回MeetingPreparationContext(role,selection,context_sha256,active)，其中active为可调用的当前认证检查，selection为当前原生/页面明确采用的原Input。模型没有范围、来源、会议或授权参数。工具读取前验证当前BOSS及active，读取后再次获取当前上下文并比较完整selection/context_sha256，再执行meeting复核；认证变化401、选择或来源变化409，取消不返回替代结果。

N3/N2接收工具时保持同一现有Registry、配置和原生Grant流程，在当前请求中提供固定selection/context_sha256及真实active检查；实际原生会话身份仍采用已有business_entry和每轮证明。不得从旧receipt、模型参数或历史文本创建该可信上下文。公共读取可直接调用meeting方法，Agent读取可注册此空参数工具；两者共享同一领域结果。现有F04保存、邀请与其他写入入口继续使用各自独立本人决定，本工具没有这些权限。

真实成功前置通过现有MeetingAPI.draft.save/confirm明确确认仅finance-note v1的会议材料，再对明确关联任务采用N03 Scope。成功检查取得当前会议v2及原始内容，当前/比较期间和区域选择的准备指标分别等于同范围正式总览结果，实际收入随期间变化；没有预设答案。重开Store并重读、并发读取及重复verify均返回相同准备摘要，objects/audit/idempotency保持。

SDK限定检查使用实际Nanobot/AgentLoop/SessionManager/ToolRegistry，复用Fc01SimulatedProvider及Fc01RuntimeRecorder记录实际事件，通过正式Runtime配置保存/验证/启用仅businessMeetingPreparationRead。模型事件生产者只读取实际工具消息，返回实际准备JSON；工具结果摘要等于领域准备摘要，Runtime记录不保存材料正文。SDK仅增加runtime_run，其他业务对象、audit及idempotency完全不变。该独立领域工具检查不登记N03公共Agent消费者验收；现有记录器的feature_id=FC01保持其真实语义，N03正式公共注册和运行归属由N3/N2接收。

异常检查包括原来源撤销、明确会议取消、材料扩大、任务版本和专题变化后拒绝原MeetingInput；参会职责到期后重新读取等待；模型注入scope参数被Registry拒绝。工具在途认证失效、选择更换、正式来源撤销和取消分别验证停止，原已返回结果保留为历史，当前采用不恢复。真正缺少关系、版本或范围内材料时仍保持WAITING_INPUT；满足条件时已经具有实际可调用结果。未知读取可以重读相同MeetingInput，没有自动保存或业务重放。
