## 2. 服务端配置与凭据引用

| 文件或位置 | 用途 | 规则 |
|---|---|---|
| `boss agent.md` | 用户提供的唯一 DeepSeek 密钥文件 | 已忽略且权限 0600；不复制到源码、命令、证据或浏览器 |
| `validation/connection.json` | 当前连接定义 | provider、公开地址、型号、协议和 credential_file 引用，不含密钥 |
| `validation/connection.example.json` | 可复制的连接模板 | 只含引用和公开参数 |
| `validation/connection.py` | 服务端读取与模型 transport 记录 | MarkdownIt 读取材料，提取唯一 credential；仅进程内设置 DEEPSEEK_API_KEY，SDK 记录不保存请求 header |
| `validation/.work/application/config.json` | 原生应用唯一有效 Runtime 配置 | 密钥只存 `${DEEPSEEK_API_KEY}`；当前管理验证保存 maxToolIterations=8、maxTokens=4096；修改后按页面重启要求执行 |
| `validation/.work/application/access.json` | 本机验证的老板与维护随机登录凭据 | 权限 0600，角色不同；仅本机服务与检查程序读取，联系人没有 token |
| `validation/.work/<run_id>/` | 独立业务数据库、SDK 会话、配置与工作区 | 每次模型共同任务重新初始化；初始快照、代码 hash 和请求证据分别保存 |
| `validation/.work/tmp/` | 中间文件与工具临时目录 | 所有验证命令设置 TMPDIR 到项目目录 |
| `validation/.work/installed/` | Packager 实际生成并启动的 .app | 独立 bundle_id：local.bossagent.validation；未配置开发者签名与公证 |
| `evidence/T02/` | 实际请求、事件、状态、DOM 文本及命令记录 | 不含模型密钥、角色 secret 或临时 token；使用 audit_evidence 复验 |

`.env.example` 仅列示独立 HTTP 服务可用的环境变量名称，不会被程序自动加载。当前模型入口读取 connection.json 指定的服务端文件，无需用户再次提供密钥。独立业务服务要求 BOSS_PROBE_TOKEN 和 MAINTAINER_PROBE_TOKEN 不同且各至少 32 字符，自动检查入口会实际生成并通过子进程环境传递。

RoleChannel 在正式 bootstrap、HTTP 和 WebSocket 边界实施老板/维护分权。原生共享 secret 仅作为底层 transport 配置使用；浏览器不能通过 contact_id 获得身份。Electron preload 只暴露固定 IPC channel，Node API 和模型凭据不进入渲染环境。

## 3. 模型协议、网络与进程

实际 Provider 为 deepseek，model_id 为 deepseek-flash，base URL 为 https://api.deepseek.com，实际 API 路径为 `/chat/completions`。请求 thinking disabled、max_tokens 4096；SDK 共同任务 maxToolIterations 12、任务总超时 120 秒；管理验证后的应用 maxToolIterations 8。原生 SDK 会使用流式请求，include_usage=true；服务 response_id、HTTP 状态、工具参数、工具结果、usage 与错误都有原始证据。

HTTP header 没有返回 request_id 时保留 null；流式标识来自官方 SDK 解码的真实服务对象。没有使用另一模型替代失败，没有手写 SSE parser。DeepSeek 配置不使用上游仅向 OpenAI Provider 提供的 apiType 字段。型号或 API 类型改变后必须重新检查。

联网实际条件：官方 `/models`、DeepSeek 模型请求、PyPI、GitHub API/codeload 和 npm 下载成功。普通 GitHub release 地址曾无法完成传输，官方资产 API 的相同二进制完成下载和 hash 校验。受限执行环境下网络、本地监听和桌面程序使用工具授权运行，相关实际执行已获授权。尚未执行设备断网后恢复过程，不能将本地桌面运行解释为模型离线可用。

| 端口 | 实际程序与责任 | 范围 |
|---|---|---|
| 8871 | application 内的真实模拟业务 HTTP | 127.0.0.1；老板与维护分别认证 |
| 8872 | 固定上游 WebUI/HTTP/WebSocket + RoleChannel | 127.0.0.1；实际两端页面及正式 API |
| 8873 | check_controls 的独立业务服务 | 仅检查期间运行 |
| 8874 | fault_probe 的实际故障业务服务 | 仅检查期间运行；503/延迟由获准模拟配置决定 |
| 8875 | check_local 的独立业务服务 | 仅检查期间运行；独立复算、重启及权限检查 |

当前 application 没有启动 Gateway health 18791。历史 upstream.py 仅用于独立原生调查，正式选型验证以 application.py 为集成入口。

Electron 主进程拥有 Python 子进程；应用进程通过 FileLock 防止重复执行。CronService 在 Python 进程运行，SDK 本身不启动计划。最后窗口关闭和完整退出都会停止 Python 及 Cron；重复启动激活已有窗口，不新增服务。实际重启后重新查询正式任务与发件箱。Dream、heartbeat、自动 compact 关闭；没有默认后台常驻、自启动或自动更新。

## 4. 可重复运行的工程与命令

以下命令在项目目录执行。初次安装需要可用网络；实际 API 和 DOM/桌面检查需要本机执行权限。所有检查生成新的独立证据目录，不使用模拟模型响应。

```bash
mkdir -p validation/.work/tmp validation/.work/upstream
cd validation
TMPDIR="$PWD/.work/tmp" UV_CACHE_DIR="$PWD/.work/uv-cache" uv sync --locked
```

固定源码获取及验证：

```bash
curl --fail --location --output .work/nanobot-v0.3.5.tar.gz https://codeload.github.com/HKUDS/nanobot/tar.gz/refs/tags/v0.3.5
shasum -a 256 .work/nanobot-v0.3.5.tar.gz
tar -xzf .work/nanobot-v0.3.5.tar.gz -C .work/upstream
curl --fail --location --output .work/nanobot-annotated-tag.json https://api.github.com/repos/HKUDS/nanobot/git/tags/b9857d7455e75bea5ca5d124fedc7ab00aa31c70
```

归档 SHA-256 必须为 `907d179f428ca321236058efef721f942eb11917d3874887d37b33fd0e208525`。进入 `validation/.work/upstream/nanobot-0.3.5/webui/` 构建实际前端：

```bash
TMPDIR="$PWD/../../../tmp" npm_config_cache="$PWD/../../../npm-cache" npm ci
TMPDIR="$PWD/../../../tmp" npm run build
```

回到 validation 目录执行真实业务与模型检查：

```bash
TMPDIR="$PWD/.work/tmp" .venv/bin/python connection.py
TMPDIR="$PWD/.work/tmp" .venv/bin/python check_runtime.py
TMPDIR="$PWD/.work/tmp" .venv/bin/python model_probe.py
TMPDIR="$PWD/.work/tmp" .venv/bin/python fault_probe.py
.venv/bin/python inventory.py
.venv/bin/python source_audit.py
.venv/bin/python summarize_evidence.py
.venv/bin/python audit_evidence.py
```

model_probe 从同一最终初始数据执行两个独立任务，保存 inputs.json、HTTP 与流式元信息、真实工具结果及新 session 重读。缺少配置、服务错误或断言不满足时命令立即终止；不能根据部分文件存在登记成功。fault_probe 在独立空间执行真实模型取消、中断、超时、轮数、写入后客户端关闭及模拟业务接口故障。

集成原生两端检查，在一个终端运行：

```bash
TMPDIR="$PWD/.work/tmp" .venv/bin/python application.py
```

另一个终端进入 validation 目录运行 `check_ui_business.py` 或 `check_admin.py`，它们通过 Chrome DOM 操作原生应用并核对实际服务，不采集截图。管理检查会在工具轮数 8 与 9 之间切换并保存，下一模型任务采用需要按原生页面要求重启；桌面检查当前明确核查 8。不要同时启动 standalone application 与桌面宿主，两者共用本机端口和单实例锁。结束 standalone application 使用该终端的 Ctrl+C，程序等待已拥有的服务和调度退出。

## 5. Electron 官方安装、打包与检查

进入 validation/desktop 目录，依赖按 package-lock 安装。Electron 45 使用官方安装入口，npm ci 本身不自动安装二进制：

```bash
TMPDIR="$PWD/../.work/tmp" npm_config_cache="$PWD/../.work/npm-cache" npm ci
```

官方二进制已经保存在 `.work/electron-v45.0.0-darwin-x64.zip`。重建时在 desktop 目录执行：

```bash
curl --fail --location --header 'Accept: application/octet-stream' --output ../.work/electron-v45.0.0-darwin-x64.zip https://api.github.com/repos/electron/electron/releases/assets/661436871
node prepare-cache.mjs
TMPDIR="$PWD/../.work/tmp" electron_config_cache="$PWD/../.work/electron-cache" node node_modules/electron/install.js
TMPDIR="$PWD/../.work/tmp" npm run package
TMPDIR="$PWD/../.work/tmp" node check-desktop.cjs
```

prepare-cache 使用官方 @electron/get Cache API，校验官方 digest 与 npm 包内 checksums 后放入官方缓存；没有修改 Electron 安装器。package.mjs 使用官方 Packager 和已校验归档。实际 `.app` 位于 `validation/.work/installed/Boss-Agent-Validation-darwin-x64/`。在项目目录启动已安装验证应用：

```bash
BOSS_VALIDATION_ROOT="$PWD/validation" TMPDIR="$PWD/validation/.work/tmp" "validation/.work/installed/Boss-Agent-Validation-darwin-x64/Boss-Agent-Validation.app/Contents/MacOS/Boss-Agent-Validation"
```

该验证宿主需要本机 validation/.venv 和项目资料目录，不具备独立产品安装器的全部交付条件；没有宣称双击启动或其他系统兼容。最终安装、签名/公证、完整产品资料路径及交接由 T25 完成。

check-system 只在用户可配合系统界面时运行，记录实际 API、音频轨道和人工观察；本次已结束采集并关闭该实例，未保存音频。用户未找到对应系统授权项目，完整系统允许/拒绝/撤销过程、休眠恢复、设备重新联网、文件选择及外部来源打开继续为未验证。

正式检查记录使用 `capture_validation.py models|runtime|faults|desktop <新的目录名称>`，在项目 evidence/T02 内保存实际命令、退出码、输入 hash 和执行期间一致性。目录名称必须全新，已有记录不会被覆盖。模型调用需要付费，费用覆盖与未知条件读取 usage-summary，D05 数值阈值仍待确定。
